# 2026-10-30

## ADR 0046 P3 完成：面板整条路径切到原生 Qt 表面（`inox_panel::native_run`）

上一轮只做了「原生表面可信」这一半，`main` 仍走 `layer.rs`。这一轮把另一半做完。

改动：

- `crates/inox-panel/src/native/qt_shell_surface.cpp`：新增 `inox-glass-v1`（**仍在同一个翻译单元里**，
  ADR §10 的「单文件」不是比喻）。`glass_create/apply/destroy/version`，管理器从
  `QWaylandDisplay::globals()` 找、`wl_registry_bind`，对象建在 Qt 的 `wl_display` 上（协议代理只能属于
  创建了那个 `wl_surface` 的连接），能力事件走 `publish(9/10)` 回到 Rust。刷新用 Qt 自己的
  `flushRequests()`，不要裸 `wl_display_flush`（会和它的读线程抢），也不要指望「Qt 下次 commit 会刷」——
  安静的面板可以永远不 commit。
- `build.rs`：`wayland-scanner` 现在按表生成两份协议（shell + glass），每份一个 `cc::Build`（**C 不能
  被 `cpp(true)` 编**，理由同上一轮：C++ 里命名空间作用域 `const` 是内部链接）。
- `src/native_surface.rs`：`Event::GlassCapabilities`/`LiquidCapabilities` + `Surface::{start_glass, glass,
  glass_version}`；`Batch` 实现 `inox_glass::GlassTarget`，让 `Request::apply` 仍是「哪些请求该发」的唯一
  实现（v1 不发 `set_corner_radii`/`set_refraction`）。
- **`src/native_run.rs`（新，主要工作量）**：`Panel` 状态机 + `run` 循环。
  - `role_of`（taskbar/menubar→Panel，dock→Dock）、`geometry_of`（`PanelPlacement`→协议字段）、
    `keyboard_of`；`parse_action`（QML 的 `{"type":"tap"/"hover"}` → `Action`）。
  - `Panel::step` = 排空事件 → 排空 QML 动作 → 窗口服务命令 →（到点）`Tick` → `sync`（放置/投影/玻璃）。
  - `run`：`Signals` 先建（Qt 会起事件线程，信号掩码必须在它前面）→ `Panel::start` → 第二条
    `wayland-client` 连接（只绑 `inox-window-manager-v1`）→ `calloop` 的 signals/ping/Generic →
    `dispatch(Some(16ms))` + `pump()`。
  - `serve()` 单独一个函数，让 `teardown()` 在**所有**退出路径上都执行。
- `main.rs`：`run()` 两个 `cfg` 版本（native_surface → native_run，否则 layer），编译期选腿，**无运行时开关**。
- 测试：`headless_tests/native.rs` 从 2 个用例扩到 7 个（裸表面、面板循环×2、**shipped 二进制**
  真的被 `main` 起来并完成放置、玻璃 pane 被合成器回答）；`headless_tests::protocol` 门控到
  `cfg(not(native_surface))`（原生构建里 `main` 建的是 shell 表面，拿 layer-shell 替身驱动它就是在断言
  「面板不是它自己」）。
- `#![cfg_attr(any(not(test), native_surface), allow(dead_code))]`：原生构建里 `layer` 的协议半边不可达。
- 文档：ADR 0046 落地状态、迁移契约 §1/§3/§11、panel AGENTS（新增「运行路径」一节）、book 的
  components/overview/protocols、README 一段。

踩到的坑：

- `Anchors::insert` 是私有的 → 测试里别手搓 `PanelPlacement`，用 `PanelPlacement::derive(&config)`。
- `tracing` 的字段不能是 `Cow<str>`（`%String::from_utf8_lossy(..)`），要写 `action = %String::…`。
- `pointer_button(275)` = BTN_SIDE = `Button::Back`，**能解析**；「这个条目对侧键没有意义」是
  `Entry::action_for` 的判断，不是解析器的。
- **E2E 里别用固定 sleep 判断「还活着」**：并行跑测试时 QML/DBus 初始化能拖过 1.5 s。改成把子进程
  stdout 重定向到文件、轮询「native inox_shell_surface_v1 surface」这一行，再断言进程仍在。

验证（本机，`TMPDIR=~/.cache/inox-tmp`）：`cargo test -p inox-panel --all-features` 367 绿
（含 `INOX_SHELL_E2E=1` 的 7 个真实合成器用例）；`INOX_NATIVE_SURFACE=0` 下 346 绿（含 13 个
layer-shell 协议用例）；两套配置的 `clippy --all-targets --all-features -D warnings` 都干净；
`cargo doc -p inox-panel`（`RUSTDOCFLAGS=-D warnings`）干净；`cargo fmt --all --check` 干净；
`cargo check --workspace --all-targets --all-features` 干净；`cargo test -p inox-integration --test layering`
17 绿；`mdbook build docs/book` 通过。

未做（按 ADR 顺序，且都有硬前提）：

- **P4（锁屏换原生渲染器）**：`ext_session_lock_v1` 的锁表面**必须有 buffer 才能让合成器发 `locked`**，
  而本机 Qt 客户端不附着任何 buffer（无 DRI），所以这一步写了也**一条证据都拿不到**；它还是安全敏感
  改动（逐输出确认逻辑不能动）。
- **P5（删离屏腿）**：CI 的 Qt < 6.5、没有私有头，删了 CI 就没有面板可编；抬基线是 ADR 里写明的
  **独立评审**。`layer.rs`/`offscreen.cpp` 因此保留。
- 面板的菜单/工具提示仍不存在（`open_popup` 在协议层可用、合成器侧有测试，面板还没有要开的菜单）。
