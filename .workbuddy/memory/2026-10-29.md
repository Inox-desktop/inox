## 实现「打开文件/链接」（xdg-open 的非门户那条腿）

背景：仓库此前**没有**任何 `xdg-open` / `OpenURI` / `mimeapps` 实现；`inox-notifications` 的
`Outgoing::FollowLink` 被显式丢弃，`inox-portal` 只是规划中的 crate。

决定：不新建 crate（新增 crate 需 ADR + 分层表 + 打包清单），把打开器放进 `inox-launcher`，
因为它是「按目标挑应用」的同一件事，且能直接复用 `desktop_entry` 与 `exec`（`Exec` 字段码展开
与「argv 永不变成 shell 命令」的性质因此自动继承）。

改动：
- `crates/inox-common/src/paths.rs`：新增 `ENV_CONFIG_DIRS`、`DEFAULT_CONFIG_DIRS`、
  `XdgEnv::config_dirs()`、自由函数 `config_dirs()`；把 `data_dirs`/`config_dirs` 的过滤逻辑抽成
  `search_path()` 与 `split_list()`；+3 个单测。
- `crates/inox-launcher/src/open/mod.rs`：`Target`（URI 按 `x-scheme-handler/<scheme>`，file: URI 转路径）、
  `Environment`（可注入的搜索路径快照）、`resolve()`（`mimeapps::candidates` → 定位 `.desktop` →
  `desktop_entry::parse` → `exec::argv`，注册但未安装的候选**落到下一个**）、`launch()`（detach spawn）、
  `run_cli()`（退出码 0/1/2/3/4）、`opener_arguments()`（argv[0]=`inox-open` 或 `--open`）。
- `src/open/mime.rs`：scheme 判定、`%XX` 解码、shared-mime-info `globs2`/`globs` 解析（纯文本，
  不读 `mime.cache`、不做 magic 嗅探）、glob 匹配（`*` `?` `[...]`、`cs` 标志、按 weight 取最具体）。
- `src/open/mimeapps.rs`：`mimeapps.list` 规范顺序（用户 config → config dirs → data dirs →
  `defaults.list`）、`Defaults` 优先于 `Added`、`Removed` 相减、首个文件赢；纯解析 + 合并。
- `src/main.rs`：多调用入口（在 `logging::init` 之后、Qt 初始化**之前**）——`inox-open …` /
  `inox-launcher --open …`，打开链接不付 GUI 工具包启动代价；`--exec-application` 分支改为基于
  `Vec<OsString>` 切片。
- 文案：`launcher.ftl` en-US / zh-CN 各 9 条 `launcher-open-*`。
- `src/catalog_tests.rs`：`referenced_ids()` 改为**递归**扫描 `src/`（否则 `src/open/` 里的 id 会被判成
  「目录有、代码没有」）；顺带发现测试里不能写以 `launcher-` 开头的字面量，改用「句子含空格」判定。
- 打包：`packaging/install.sh`、`packaging/aur/PKGBUILD.in`、`canary/PKGBUILD` 安装
  `inox-open -> inox-launcher` 符号链接。
- 文档：launcher README / AGENTS（新增 `src/open/` 与诚实缺口）、`docs/book` 的 components.md 与 roadmap。

验证（本机）：`cargo test -p inox-launcher --bin inox-launcher` 334 passed（1 ignored 是子进程自检）、
`cargo test -p inox-integration --test layering` 17 passed、`cargo clippy -p inox-launcher -p inox-common
--all-targets -- -D warnings` 干净、`cargo fmt --all --check` 干净。真实二进制冒烟：临时 XDG 树里
`--open notes.txt` → 启动 `/bin/true` 退出 0；不存在的路径 → 2；未知扩展名 → 3；无参数 → 1；
符号链接 `inox-open` 走同名入口；真实会话里 `--open https://example.org` 按 `~/.config/mimeapps.list`
选中 `google-chrome.desktop` 并退出 0。

## 离屏 QML 架构评估（面板/锁屏）与动画、子菜单的落点

结论：生产路径上只有 `inox-panel`、`inox-lock` 真做 QML 离屏渲染（`src/offscreen.{h,cpp,rs}`），其余 5 个 QML 组件是普通 Qt 窗口。
用户提出「必须要有 QML 动画和子菜单」，核查后确认这两项**都能在离屏路线内做**，缺口是没接线而非做不到：

- **动画**：`app::TICK = 1s`（app.rs:61），commit 只在投影变化时发生（layer.rs:1548/1581），QML 里 0 个 Animation；
  软件后端的帧只在宿主 `processEvents()` 泵里产生（offscreen.cpp:110-114）。方案：宿主装自定义 `QAnimationDriver`
  并暴露 `advance(ms)`，Rust 用 `wl_surface.frame` 回调当节拍驱动 advance→render→commit，投影里带 `transition.duration_ms`
  让 QML 保持「只画」。红利：动画可确定性测试（显式推进时间戳断言中间帧）。
- **子菜单**：只能走 `zwlr_layer_surface_v1.get_popup(xdg_popup)`。合成器侧 `WlrLayerShellHandler`（state.rs:3421-3459）
  **没有实现 `new_popup`** → popup 不进 `PopupManager` → 永远收不到 initial configure；但渲染侧已经能画
  （smithay `desktop/space/wayland/layer.rs:31-48` 会遍历 popups_for_surface）；`layer_under`（state.rs:2940）不含 popup 命中，需补或用 grab 接管（grab 已实现 state.rs:3616-3665）。
  面板侧需新增 popup 腿：每个 popup 一个 wl_surface + Host + wl_shm 帧，架构上 lock 的「每表面一个 Interface」已证明可行。

建议顺序：动画帧钟 → 合成器 popup 补丁（可由 bemenu 等第三方 layer-shell 客户端验证）→ 面板 popup 腿；popup 策略应走 ADR。

## ADR 0046 + `inox-shell-v1` 协议（panel/lock 放弃离屏，改原生 Qt）

用户决定：离屏 QML 的上限是架构性的（无缝跨表面过渡、子菜单），要求改成**原生 Qt 表面**，并明确
「即使要上难维护的私有协议」。据此写了 ADR 0046 并落地协议 P0。

改动：
- `docs/adr/0046-shell-surfaces-and-native-qt.md`：决策 + 私有 ABI 授权边界 + P0–P5 阶段 + 取舍。
- `crates/inox-protocols/protocol/inox-shell-v1.xml`：`inox_shell_v1` / `inox_shell_surface_v1` /
  `inox_shell_popup_v1`。放置是**一个原子请求**（set_placement 9 参，不给 setter 兄弟）；popup 关闭权
  在合成器（`set_dismissable` + `dismiss` + `dismissed(reason)`，不交 serial）；`set_transition` 是
  提示且**无完成事件**；`workarea` 事件（layer-shell 没有）；popup 可嵌套（子菜单）。
- `crates/inox-protocols/src/shell.rs`（绑定 + 12 个元数据单测）、`tests/shell_roundtrip.rs`（3 个
  socket 往返：放置九字段逐字、popup 定位/尺寸/嵌套/关闭、被拒角色以 `closed` 到达）。
- 文档：`docs/qml-migration-contract.md` §1/§11、`docs/book/src/architecture/protocols.md`、
  `inox-protocols` / `inox-panel` / `inox-lock` 的 AGENTS、panel/lock README（都标明「过渡态」）。

**事实更正（重要，之前笔记里对，后来我 grep 错了）**：标准 popup 的**渲染**是好的——Smithay 的
`AsRenderElements for Window` 与 `for LayerSurface` 都在 `desktop/space/wayland/{window,layer}.rs`
里遍历 `PopupManager::popups_for_surface`，所以窗口菜单正常。`rg popups_for_surface crates/inox-compositor`
零命中只说明合成器**不需要**自己画，不是不画。真正的缺口是合成器没实现
`WlrLayerShellHandler::new_popup`（state.rs 只有 shell_state/new_layer_surface/ack_configure/
layer_destroyed）→ layer 表面为父的 xdg_popup 不进 `PopupManager`、收不到 initial configure、
**永远不映射**。ADR 与 book 已按这个版本表述。

关键判断：锁屏**不**进私有协议——`ext-session-lock-v1` 的「锁定帧先于 locked」是安全语义，只换渲染器；
锁屏也**永不接 IME**（输入法进程是普通客户端）。P3 的真实阻塞是 CI 的 Qt 基线：noble 只有 6.4.2，
私有头闸门要求 ≥ 6.5，需要单独评审地抬基线（`qt6-wayland-private-dev` + license-audit 白名单）。

本机验证：`cargo test -p inox-protocols --offline`（46 lib + 各集成，全绿，含 3 个新往返）、
`cargo clippy -p inox-protocols --all-targets -D warnings` 干净、`cargo doc` 无警告、
`cargo fmt --all -- --check` 干净。工作区是 `/home/rownix/Projects/Inox` 的符号链接，非 Qt crate 能直接编译
（`--offline` 即可，registry 在 `~/.cargo`）；panel/lock 需要 Qt，本机没装，改不了也验不了。

## ADR 0046 P3 第一半：panel 的原生 Qt 表面（`cfg(native_surface)`）+ 真实合成器 E2E

按 ADR 0046 的 P3 做了「原生表面可信」这一半，**没有**切换面板的 `run`（见末尾缺口）。

改动：
- `crates/inox-panel/src/native/shell_surface.h` + `qt_shell_surface.cpp`：唯一允许 `QtWaylandClient`
  私有 ABI 的翻译单元。`QWaylandShellIntegration` 子类 + `QWaylandShellSurface` 子类
  （`InoxShellSurface`/`InoxShellPopup`），三道闸门（`#if QT_VERSION < 6.5 #error`、运行期 `qVersion()`
  比较、失败即返回错误不退回 xdg/layer-shell）。公共头里只有 Qt 公开类型与整数。
- `src/native/host.{h,cpp}`：QGuiApplication + QQmlApplicationEngine + 角色安装 + `pump()`
  （`QCoreApplication::processEvents`）+ 事件队列 + QML `outbox` 动作队列。
- `src/native_bridge.rs`（**plain `cxx::bridge`，不是 cxx-qt**）+ `src/native_surface.rs`
  （`Surface`/`Event`/`Geometry`，13 个纯单测）。
- `build.rs`：`wayland-scanner public-code` 生成 inox-shell-v1 的 C 绑定，`cc` 编 C 与 C++，
  `cargo:rustc-cfg=native_surface`。
- QML：`Main.qml` 加 `outbox`/`dispatch()`/`entryAt()`/`TapHandler`/`HoverHandler`，
  `visible: !inoxHostNative`（原生宿主先装角色再显示）。
- `view.rs`：投影里加 `entries`（id/矩形/enabled）+ `Scene::action_of(id)`，+1 测试。
- `src/headless_tests/native.rs`：真实 `inox-compositor --headless` + 子进程 Qt 客户端，
  断言 capabilities(15,250)、configure 1280×28、workarea、popup configure 180×240。`INOX_SHELL_E2E=1` 才跑。

踩到的坑（都值得记住）：
- **`wayland-scanner private-code` 生成 hidden 符号**，静态库里 `nm` 看到 `d`/`t`，链接报
  `undefined symbol: inox_shell_v1_interface`；改用 `public-code`。
- **`.c` 不能被 `cc` 的 `cpp(true)` 编**：C++ 里命名空间作用域的 `const` 是内部链接，符号变成
  `_ZL23inox_shell_v1_interface`。生成码单独一个 `cc::Build`（C），C++ 另一个。
- `emit` 是 Qt 宏，C++ 里不能当函数名（改成 `publish`）。
- cxx 的 `&mut QString` 对应 C++ 的 `QString&`（不是 `QString*`）；`take_event` 的 out 参数同理。
- `#[cxx::bridge(namespace = ...)]` 会把所有类型都放进那个命名空间，包括你 include 的头里的 —— 用非命名
  空间桥。
- **本机 Qt 6.12 作为 wayland 客户端连我们自己的 headless 合成器是可行的**（角色/放置/configure 全通），
  但 `QWindow::isExposed()` 恒为假、`frameSwapped` 从不触发 ⇒ 不附着 buffer ⇒ 合成器侧永远看不到
  「已映射」的表面，popup 的 `dismissed` 也就不发生。无 DRI 的宿主上无法证明出图。

验证（本机；`TMPDIR=~/.cache/inox-tmp`，`/tmp` 只有 10M 会 `No space left`）：
`cargo test -p inox-panel --all-features` 362 绿；`INOX_SHELL_E2E=1 cargo test -p inox-panel headless_tests::native`
2 绿；`cargo clippy -p inox-panel --all-targets --all-features -- -D warnings` 干净；`cargo doc -p inox-panel`
（RUSTDOCFLAGS=-D warnings）干净；`cargo fmt --all --check` 干净；`cargo test -p inox-integration --test layering`
17 绿；`cargo check --workspace --all-targets` 干净。`cargo deny check licenses` 在本机跑不了（往 registry
解包时 mtime 被拒），不是许可问题。

**不用 cargo feature 表达「能不能编原生路径」**：工作区以 `--all-features` 验收，那会把一个需要更新 Qt 的
开关在每台 CI 上都打开。改成 `build.rs` 探针（`qmake -query QT_VERSION` + 四个模块的私有头目录），
`INOX_NATIVE_SURFACE=0` 可强制走离屏。

未做（下一步）：① 面板 `run` 切到原生宿主（要重写循环归属、玻璃走 Qt 连接、重写 protocol 测试）；
② 在有 DRI 的机器上先让一个最小 QQuickWindow 出帧，再谈切换；③ 抬 CI 的 Qt 基线（独立评审）。
