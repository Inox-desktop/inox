# `session-control-v1` — the session's own control socket

- 状态：**normative**（规范文本）。类型与实现见 `inox-protocols::control`；服务端在
  `inox-session`，客户端在 `inox-lock --request-lock`。
- 传输：Unix 域套接字，路径 `$XDG_RUNTIME_DIR/inox-session/control.sock`
  （可用 `INOX_SESSION_CONTROL` 覆盖）。目录属主为会话用户，权限 `0700`；套接字文件 `0600`。
- 版本：接口名 `session-control-v1`。协议没有版本字段：整个契约是一个动词。

## 1. 为什么需要它

会话监督进程（`inox-session`）是**唯一持有会话锁令牌**的进程，因此只有它能启动可信锁屏客户端。
手动锁定（快捷键、CLI）与空闲触发的锁定都需要「请会话去锁」这条通道。它不能走 Wayland：
`inox-ipc` 是任何能连合成器的客户端都能绑定的全局对象，把「锁我屏幕」放上去等于对所有应用开放
（沙箱应用连不上 `0700` 的 runtime 目录，但连得上 Wayland socket）。因此它是一条私有 Unix 套接字，
只接受会话用户自己的连接。

## 2. 帧格式

```
line = word "\n"
word = 1..=64 字节的 ASCII，不含换行
```

- 一条连接**一个**请求：客户端连接、写一行、读一行、连接结束，服务端随后关闭。
- 请求超出 64 字节、没有换行符、或为空行：服务端不回复并关闭连接（客户端可诊断为
  `malformed`）。协议不做重同步。
- 不认识的动词：回 `unknown\n`。
- 服务端读请求有超时（实现为 250 ms 量级）；超时按 `malformed` 处理。

### 请求（客户端 → 服务端）

| 动词 | 含义 |
|------|------|
| `lock` | 启动可信锁屏客户端（若尚未运行） |

**没有第二个动词，也没有参数。** 任何可能命名命令、账号、显示器或令牌的字段都会把这条 socket
变成「让会话做事」的入口；这里允许的最坏情况是请求者把自己锁在外面。传输值（哪个程序、哪份环境、
哪个令牌）全部来自会话启动配置。

### 答复（服务端 → 客户端）

| 答复 | 含义 |
|------|------|
| `ok` | 请求已被接受，监督进程已要求锁服务启动 |
| `busy` | 现在没有可以启动的东西：会话尚未就绪，或已有一个锁请求在途 |
| `unknown` | 本会话没有这个服务；调用者应换用更新的会话，而不是重试 |

**`ok` 不是锁定确认。** 会话是否真的被遮蔽，权威答案来自合成器在 `inox-ipc` 上的
`session_lock_state` 事件。把 `ok` 当成「已锁定」的调用者信任了系统错误的那一半。

## 3. 身份与授权

- 服务端在**读任何字节之前**用 `SO_PEERCRED` 取得对端 uid，只接受与自身相同的 uid；
  其它连接直接关闭，不回复。
- socket 的存在本身就是「这个会话可以被要求锁定」的证据；它不是能力令牌，也不能解锁任何东西。
  解锁永远只由 `auth-v1` 的一次成功答复构成（见 `auth-v1.md`）。
- 令牌（`INOX_LOCK_TOKEN`）**绝不出现在这条通道上**：它由监督进程在 spawn 锁客户端时通过环境投递。

## 4. 一次手动锁定的时序

```
client ── connect ──▶ session
       ── "lock\n" ─▶ peer uid 校验 → 监督进程按需启动 inox-lock --take-lock（带令牌环境）
       ◀── "ok\n"  ──
                        inox-lock claim_lock_role(token) ─▶ 合成器
                        合成器遮蔽所有输出并 locked ─▶ session_lock_state=locked（观察者可见）
钥匙按下 ─▶ 提示输入口令 ─▶ auth-v1 Accepted ─▶ unlock_and_destroy
```

## 5. 失败语义

- 没有 socket：会话不在跑（或不是本用户的）。客户端报「没有可请求的会话」并以非零码退出，
  **不得**退回到「自己假装锁屏」。
- `busy`：调用者是幂等的——再按一次快捷键即可；客户端以 0 退出（请求已被理解）。
- 锁服务在取锁前崩溃：监督进程不做无界重启（已锁时第二次取锁会被合成器拒绝），
  调用者需要重新请求。这是有意的：自动重启只会制造一串被拒绝的日志。

## 6. 变更规则

契约是私有的、unstable 的，但**破坏性变更必须先改这份文档**并同步 `inox-protocols::control`
的类型与测试、`inox-session` 的服务端与测试、`inox-lock` 的 `--request-lock` 与文案。
