# Inox UI 设计规范

- 状态：本规范只**收紧**既有约束，不放宽 [硬性规则速查](https://github.com/Inox-desktop/inox/blob/main/README.md#硬性规则速查) 的任何硬性规则。
- 适用范围：所有绘制 QML 界面的组件 —— `inox-panel`、`inox-launcher`、`inox-notifications`、`inox-settings`、`inox-lock`、`inox-wallpaper`、`inox-greet`。
- 依据：[主题与设计令牌](../book/src/configuration/theme.md)、[验收规范](./acceptance.md) 的 Q01–Q03、[组件清单](../book/src/architecture/components.md)。
- 设计原则的来源：Apple《Designing Fluid Interfaces》与 Emil Kowalski 的界面工程经验 —— 即时反馈、清晰层次、状态可见、克制动画、看不见的细节累积成手感。这些原则在此被翻译成 **QML + Qt Quick + 设计令牌** 的可执行规则，而不是网页 CSS 的写法。

本页回答的是「令牌已经有了，界面该怎么用它」。令牌本身的取值与 schema 以 [主题与设计令牌](../book/src/configuration/theme.md) 为准，本页不定义新令牌。

## 1. 令牌纪律

`theme.rs` 是每个 crate 里**唯一**把令牌变成颜色与样式的地方，`view.rs` 只调用它。

| 量 | 来源 | 说明 |
|----|------|------|
| 颜色 | `tokens.colors.*` | 11 个颜色令牌，不得在组件里新增颜色 |
| 间距 | `tokens.spacing.{xs,sm,md,lg,xl}` | 2 / 4 / 8 / 16 / 32 |
| 圆角 | `tokens.radii.{sm,md,lg}` | 4 / 8 / 12 |
| 描边宽度 | `spacing.xs / 2` | 派生常量，命名后放在 `theme.rs` |
| 焦点环宽度 | `spacing.xs` | 派生，直接取令牌 |
| 字号 | `spacing.lg × 角色倍数 × typography.scale` | 令牌集没有字号，倍数写成 `theme.rs` 里的具名常量 |
| 头像圆章直径 | `spacing.lg × 具名倍数 × typography.scale` | 倍数 3.0（头像）/ 2.0（列表行内），写成 `MEDALLION_RATIO` / `ROW_MEDALLION_RATIO`，随字号缩放 |
| 遮罩 | `colors.background` 按百分比降 alpha | 比例写成 `theme.rs` 里的具名常量 |
| 动效时长 | `tokens.motion.{fast,normal,slow}_ms` | 见 §8 |

**禁止**在 `view.rs` 出现字面量颜色（`Color::from_*`、`Color::BLACK`）、字面量尺寸（`padding(12)`、`size(15)`、`radius(6)`）。`Padding { .. }` 的每个字段、`spacing(..)` 的实参都必须是 `PanelGeometry`/`Geometry` 之类的派生值或令牌本身。

## 2. 类型层次

四个角色，倍数与用途固定；默认令牌（base = 16 × `typography.scale`）下的取值写在括号里。

| 角色 | 倍数 | 默认 | 用途 |
|------|------|------|------|
| `title` | 1.5 × base | 24 | 窗口/页面主标题，每个表面至多一个 |
| `heading` | 1.25 × base | 20 | 卡片、分组、页内小节标题 |
| `body` | 1.0 × base | 16 | 正文、控件标签、当前值、按钮文字 |
| `caption` | 0.875 × base | 14 | 说明、单位、状态句、次要元信息 |

- 强调用 `Font { weight: Weight::Bold, ..Font::DEFAULT }`，**不靠**继续放大字号；同一屏里不要出现第三种字重。
- **例外（启动器、命令面板）**：表面的输入框就是该表面的主角，其输入文本可以用 `title` 角色 —— 此时该表面不再另设标题，输入框必须是屏幕上视觉重量最高的元素。
- `caption` 不得小于 `0.75 × base`；`title`/`heading`/`body`/`caption` 之外的中间尺寸不新增。
- `inox-panel` 的 base 由面板高度推导（`height / 2 × scale`，见该 crate 的 `theme.rs`），其余窗口型表面用 `spacing.lg × scale`。两处都必须对 200% 缩放给出不裁切的证据（§7）。

## 3. 间距节奏

| 关系 | 令牌 |
|------|------|
| 页面/窗口内边距 | `xl` |
| 区块（卡片、分组）之间 | `lg` |
| 页头标题与说明之间 | `sm` |
| 标签与它的控件之间 | `sm` |
| 同一组内相邻条目之间 | `sm` |
| 行内元素（图标与文字、输入与单位）之间 | `sm` |
| 卡片内边距 | `lg` |
| 控件左右内边距 | `md` |
| 控件上下内边距 | ≥ `sm`，且控件总高度 ≥ `xl` |
| 状态条、提示条内边距 | `md` |

节奏靠**一个有意义的间距**建立（分组用 `lg`、组内用 `sm`），不是靠均匀铺开的空行。界面里允许留白，但留白必须服务分组：相关的东西靠近，不相关的东西分开。

令牌刻度与 §4 的目标高度会冲突：16 px 正文加上 `sm` 的上下内边距只有 24 px，达不到 32 px 的交互目标。**以 §4 为准** —— 控件的上下内边距取到满足目标高度为止（通常正好是 `md`），横向内边距仍按上表。

## 4. 控件几何与分组

- **交互目标高度 ≥ `spacing.xl`（32）**，并随字体缩放一起增长。禁止用固定高度把放大后的文字截断。
- **条带的例外**：`inox-panel` 的条目高度 = 用户配置的条带高度 − `spacing.xs` 的上下内缩。条带高度是用户配置，条目不得超出它；面板因此只用 `xs` 作视觉内缩，其余窗口型表面仍按 ≥ 32 的目标高度。
- **宽度按语义**，禁止把短字段拉满窗口：数值/单位类 ≤ 6 × `xl`；连接器、格式串、路径、命令 ≤ 12 × `xl`；说明性长文本与表格类用 `Fill`。
- **圆角**：`sm` 用于输入框、按钮、标签、开关；`md` 用于卡片、分组、弹窗、菜单、通知；`lg` 用于窗口与全屏表面。同一个表面内不混用两种圆角做同一类东西。
- **边框**：只使用 hairline，颜色 `border`；卡片 = `surface` 背景 + hairline 描边 + `md` 圆角 + `lg` 内边距。卡片不再叠加重阴影，弹窗可以用一层低对比阴影（`border` 色，偏移与模糊都用 hairline 的倍数）。
- **表面层次**：`background`（窗口底）→ `surface`（卡片、面板、托盘）→ `surface_variant`（悬停、选中、次级区块）。禁止把浅色表面叠在浅色表面上导致对比下降；正文对比以 §7 为准。
- **有边界的分组**：同一卡片里只放同一主题的内容；换主题必须换卡片或换区块。不要用无意义的分隔线或空行填充空间。

## 5. 状态可见性

每个可交互元素必须把五个状态画成**两两可辨**的样子。

| 状态 | 画法 |
|------|------|
| 静止 | 无背景，文字 `text`，描边 `border` |
| 悬停 | 背景 `surface_variant` |
| 按下 | 背景 `accent`，文字 `on_accent` |
| 焦点 | `accent` 描边，宽度 = `spacing.xs`；当背景已是 `accent` 时改用 `on_accent` 描边（否则焦点不可见） |
| 禁用 | 文字 `text_muted`，无背景，并且**必须给出可读原因**；默认不进焦点序列 |

- **例外（可达的「不可用」）**：当某个表面把「为什么不可用」本身做成一行（启动器的禁用条目），该行可以留在键盘序列里，但必须画成禁用样式、进入它只能读到原因、`Enter` 不得触发任何动作。crate 级 `AGENTS.md` 写明的键盘契约优先于本条的默认值，冲突时以 crate 为准并在报告中说明。

- 反馈必须发生在**按下**的瞬间，不能等释放才出现。
- **已填 `accent` 的控件**（每屏唯一的主动作、当前项）：悬停不改变填充 —— 令牌里没有 `accent` 的 hover 变体，换成 `surface_variant` 会让它读起来像禁用；改在 `accent` 上加一圈 `on_accent` 的 hairline 作为悬停线索，按压仍用 `accent` 与 `on_accent` 互换，焦点仍用描边表示。
- 焦点在整屏**唯一且可见**；键盘顺序与视觉顺序一致（Q01）。
- 破坏性动作（移除条目、恢复默认）用 `danger` 描边或 `danger` 文字，不整块填 `accent`；`accent` 只留给每屏一个主动作。
- **例外（身份，不是动作）**：用 `accent` 给「条目身份」上色（启动器每行的图标底色）是可接受的，前提是它与选中态**整体形状不同**（选中是整行填充、身份是小方块），用户一眼仍能指出「当前选中是哪一个」；不得让身份色与选中态同形同色。
- 选中态与焦点态必须能同时存在且都被看见：选中用背景，焦点用描边。

## 6. 反馈与状态文案

- 每个表面必须覆盖：**进行中 / 空态 / 错误（含重试）/ 禁用（含原因）/ 成功或已生效**。缺一个都算未完成。
- 状态必须在界面上读得出来，不能只写进日志或只靠颜色；颜色是辅助，句子是主体。
- 文案全部走 Fluent：`en-US` 与 `zh-CN` 同步，占位符一致；动态内容作为参数传入，不拼进消息 id。
- 界面不得声称未确认的成功（例如尚未回读的「已生效」），也不得提供做不到的动作。

## 7. 无障碍与缩放

- 核心任务（启动器搜索启动、面板切窗、设置应用/取消、锁屏路径、托盘菜单）必须能只用键盘完成（Q01）。
- 200% 字体缩放：不裁切、不重叠、不出现无法触达的横向溢出；数字与其单位、标签与其控件不得因缩放分家（Q02）。
- 尊重高对比主题：正文与它的背景保持可读对比；`text_muted` 只用于次要信息，不用于必须读到的值。
- 减少动态：在不依赖动画的可见终态之外，不新增必须靠动画才能看见的状态（§8）。

## 8. 动效（可选、克制）

- 只在**瞬时表面**（弹窗、菜单、通知、状态过渡）使用；键盘高频动作（切窗、搜索、开关）不加动画。
- 时长只能取 `motion.fast_ms` / `normal_ms` / `slow_ms`，UI 动效一律 < 300 ms，缓动偏「快出」（ease-out 类）。
- 动画不得阻塞输入，不得让界面在动画期间忽略事件。
- 进入动画必须有**非动画的可见终态**：没有接入减少动态偏好的组件，不得把可见性只放在动画上。

## 9. 常见反例与改法

| 之前 | 之后 | 为什么 |
|------|------|--------|
| 短数字输入框拉满窗口宽度 | 宽度 ≤ 6 × `xl`，标签与控件左对齐同列 | 宽度承载语义；全宽字段让用户误以为要填长文本，也浪费 1000 px |
| 标题、小节、正文几乎同字号，只靠字重区分 | `title` / `heading` / `body` / `caption` 四角色 | 层次要让「先看什么」在扫一眼时就成立 |
| 页面顶部密集排布，底部一大片空白 | 分组用卡片（`surface` + `md` 圆角 + `lg` 内边距），组间 `lg` | 空白要服务分组，不是布局的副产品 |
| 悬停、按下、焦点都只是「亮一点」 | 五状态用背景 / 描边 / 文字色三者组合区分 | 键盘与指针用户都要能确定「现在在哪、按了什么」 |
| 禁用控件只是变灰，不写原因 | 灰 + 可读原因（Fluent 文案） | 用户需要知道怎么把它变成可用 |
| 状态只在日志里，界面说「保存成功」 | 界面如实区分进行中 / 已保存 / 已生效 / 失败可重试 | 界面只能声称系统真正确认过的事实 |

## 10. 落地清单（每个 crate 逐条核对）

- [ ] `theme.rs` 导出字号四角色、间距、圆角、hairline、焦点环、状态样式，并有单元测试
- [ ] `view.rs` 内没有字面量颜色与尺寸（grep 可查）
- [ ] 五种交互状态两两可辨，有单元测试或像素断言
- [ ] 层次正确：每个表面至多一个 `title`，分组有 `heading`，说明用 `caption`
- [ ] 间距全部来自令牌；分组用卡片而不是空行
- [ ] 短字段按语义宽度，未被拉满
- [ ] 空 / 错 / 禁用 / 进行中状态都有文案与原因，且可操作（可重试）
- [ ] `en-US` 与 `zh-CN` catalog 一致（`compare_catalogs`）
- [ ] 200% 缩放与 1280×720 渲染有 before/after 证据
- [ ] `cargo fmt` / `clippy -D warnings` / `doc` 自检通过（验收仍以 CI 为准）

## 11. 明确不做

- **不新增设计令牌**：令牌 schema 的变更属配置模型 / 0014 的范围，本规范只使用现有令牌与 §1 的派生。
- **不新增依赖、不新增 crate、不引入 layer-shell 宿主**。
- **不改变领域契约与状态机语义**：界面重做不改变任何 `Message`/`update` 的既有事实与跨进程契约；既有验收断言随实际行为一并更新，不放宽。
- **不为「更好看」牺牲既有的键盘、缩放、文案与状态断言。**

## 12. 玻璃材质（glass / backdrop blur）

玻璃（磨砂）材质只用于**悬浮的界面外壳**：面板的菜单栏与 dock、浮动菜单、通知栈。它不得铺在承载正文的大面积内容上 —— 玻璃降低了背景与文字的可读对比，正文按 §7 仍必须清晰可读。

> 说明：`tokens.glass` 是由记录、加在 `inox-config` 上的材质令牌组；§11 的「不新增设计令牌」约束的是那一次界面重做的范围，不阻止这个已经有 ADR 的令牌组。

- **材质只有一处来源**：`tokens.glass`（`tint` / `tint_strong` / `highlight` / `shade` / `blur`，见[主题与设计令牌](../book/src/configuration/theme.md)）。组件**不得**自己写死 tint 或自造一个「更透明一点的 `surface`」。一块玻璃 = 铺在透明表面上的半透明 `tint` + 顶边一道 `highlight` 发丝线 + 底边一道 `shade`；除 §4 允许的那一层低对比阴影外不再叠加阴影。按下/强调态的加深用 `tint_strong`，不新增颜色。
- **背景模糊由合成器完成，组件只提出请求**：组件经 `inox-glass-v1`（`get_glass` + `set_region` + `set_radius`）请求模糊该表面背后的区域，半径取 `tokens.glass.blur`；`capabilities` 报告合成器接受的**最大**半径（`set_radius` 超限会被钳制，不是错误）。半径与区域是表面局部逻辑坐标，区域越界会被裁剪，非正尺寸表示「停止磨砂」。
- **拿不到就降级，不谎报**：`capabilities = 0`、绑定不到 `inox_glass_manager_v1`、或表面没有 layer 角色时，组件必须画**纯半透明**（`tint` / `highlight` / `shade` 照旧，只是没有背景软化），并可以按 `glass.blur = 0` 的语义显式关闭模糊。**不得**把没有拿到的模糊画成「看起来像模糊」的假象，也不得因拿不到能力而反复重建对象（只有表面**后来获得**了 layer 角色才允许销毁重问，见 ）。
- **成本与范围**：每个表面至多一个 glass 对象；模糊只作用于该表面自己的区域，普通窗口（非 layer 表面）不会被磨砂，也不会去磨砂它。锁定会话不施加任何磨砂 —— 锁定时普通层根本不参与合成。不做动画、放大或「液态玻璃」类的动态半径。
- **键盘与状态不受影响**：玻璃是纯视觉层，不得改变焦点、命中区域、可读状态或键盘顺序（§5、§7）。文字与图标压在半透明材质上时，仍须满足 §7 的对比要求；做不到就加深 `tint` 而不是牺牲文字。
- **面板的菜单栏与 dock 是这一材质的第一个消费者**：`inox-panel` 的 `theme.rs` 是唯一把 `tokens.glass` 变成窗格填充的地方 —— 一块窗格是「半透明 `tint` + 顶边 `highlight` + 底边 `shade`」的竖直渐变（两道发丝边由窗格自身的填充画出，不额外占一行控件：那一行会被撑满整个表面，而 dock 只应有图块那么宽），键盘导航聚焦时用 `tint_strong`。面板**不自己画模糊**：`glass.blur` 只是向合成器提出的半径，合成器侧的磨砂由玻璃协议的 leg 落地；在那之前面板画的是纯半透明，`tests/render.rs` 用合成在选定背景上的像素证明它确实是半透明，而不是不透明的 `surface`。
