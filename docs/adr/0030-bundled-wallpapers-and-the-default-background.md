# ADR 0030: 内置壁纸、默认背景与 `wallpaper.image` 的取值语义

- 状态：proposed
- 日期：2026-10-17
- 决策者：架构组与组件（wallpaper / settings / config）维护者
- 批准记录：待补（人类评审 PR / 评论与日期；合并草案不等于接受）
- 关系：补充 ADR 0009（配置模型与热重载）、ADR 0013（Shell 服务与交互契约）；**改变** `wallpaper.image`
  缺席时的既有行为（原为「绘制主题背景」），并为其引入一个保留取值。不改变任何键名，因此不是配置格式的破坏性变更。

## 背景

PRD §9.1 规定了配置目录布局，§12 规定了打包与随附资源；ADR 0009 确立「缺失字段一律回退默认值」，
ADR 0013 把壁纸建模为声明式服务（配置描述结果，组件负责达成）。在当前实现中，`[wallpaper] image` 缺席时
合成结果就是**主题背景**（`selection` 无路径、界面进入空态），用户必须自己提供一个图像路径才能看到图像。

这带来两个问题：

1. **新装会话没有任何图像。** 一台刚装好的 Inox 只显示纯色主题背景，产品上谈不上「开箱可用」；而这恰好是
   一个不需要任何设备能力、E0/E1 即可验证的默认值。
2. **选择壁纸没有入口。** `inox-settings` 只有一个「图像路径」文本框（`Field::WallpaperImage`，`Value::Text`），
   用户必须知道文件系统上的路径并手写。仓库里已经有一组候选图像，却没有一条让用户**挑选**的路径。

同时约束是明确的：

- 《AGENTS.md》§4：Shell 组件只消费主题令牌；L3 的 `inox-settings` **不得**依赖同层的 `inox-wallpaper`
  （`cargo test -p inox-integration --test layering` 机械强制）。因此「有哪些内置壁纸」这一事实**不能**放在
  `inox-wallpaper` 里由 `inox-settings` 读取；它必须位于两者都能合法依赖的层（L1 的 `inox-config`）。
- 「哪些图像随发行版安装」是**安装的属性**，不是二进制或库的属性：同一份代码在不同发行版/打包方式下应能装
  在不同的目录，甚至一个都不装（由 packager 决定）。
- 图像不得由 `update` 在交互循环里解码（ADR 0013）；也没有现成的缩略图资源管线。

## 决策驱动因素与备选

| 方案 | 收益 | 成本 / 风险 | 选择或否决依据 |
|------|------|-------------|----------------|
| 保持现状：`image` 缺席＝主题背景，用户自备路径 | 零改动；无许可/打包负担 | 新装无图像；选择只能手写路径；产品缺一个已具备素材的能力 | 否决：素材已在仓库，能力却不对用户开放 |
| 把图像 `include_bytes!` 进二进制 | 不依赖安装布局；一个可执行文件即带全部 | 二进制膨胀数 MB；L1 `inox-config`（或各 L3 组件）被迫承载字节；packager 无法按需剔除；许可风险被绑定进代码 | 否决：把「安装资源」错误地做进「代码」 |
| **图像作为数据文件安装 + L1 目录清单 + Settings 选择控件** | 分层合法（清单在 L1）；packager 可增删；无新 Rust 依赖；解码仍在 wallpaper 组件 | 需要安装步骤、路径解析与一处行为变更 | **采纳** |
| 由合成器（L2）拥有墙纸资源并通过协议下发 | 单一权威 | 合成器与 Shell 不通过 Rust 依赖耦合（根级 §2），把图像资源塞进合成器既越层又在 M3 之前不可得；ADR 0013 已把壁纸定位为 L3 客户端 | 否决：越层且与既有契约冲突 |

## 决策

1. **目录清单在 L1。** 新增 `inox-config::wallpapers`：`BUNDLED: &[BundledWallpaper]`，每项含
   `id`（写入 `wallpaper.image` 的稳定标识，一经发布不再更改）、`file`（安装后的文件名）、`author`、
   `source`、`license`。另有 `DEFAULT_ID`（会话默认壁纸）与 `BACKGROUND_ID = "none"`（显式「主题背景」）。
   清单**不含路径**：文件装在哪里是安装的属性，由步骤 2 解析。

2. **文件作为数据文件安装。** 图像位于仓库根的 `data/wallpapers/`，安装到
   `$XDG_DATA_DIRS/inox/wallpapers/`。解析在 `inox-common::paths` 内（`data_dirs` 与
   `inox_wallpaper_dirs()`），并提供 `INOX_WALLPAPER_DIR`（绝对路径）作为覆盖，供源码检出、测试与非常规布局使用。
   `inox-wallpaper` 与 `inox-settings` 都只读清单、不构造路径；「实际路径」是运行时事实。

3. **`wallpaper.image` 的取值语义**（同一套规则由组件与设置窗口共同实现）：

   | 配置值 | 含义 |
   |--------|------|
   | 键**缺席**（`None`） | **内置默认壁纸**（`DEFAULT_ID`） |
   | `"none"` | 主题背景（有意的「无图像」） |
   | 清单中的某个 `id` | 该内置壁纸 |
   | 其它字符串 | 文件路径；相对路径相对于配置文件所在目录解析 |

   这是**行为变更**：键缺席从「主题背景」变为「默认壁纸」。想要旧行为的用户写 `image = "none"`。

4. **选择控件在 Settings。** `inox-settings` 的 `Field::WallpaperImage` 由文本框改为**选择控件**
   （复用既有 `Control::choices` 机制，不新增 `ControlKind`）：选项＝「默认壁纸」＋清单中每张壁纸＋
   「主题背景」。标签是 Settings 自己的 Fluent 文案；清单的**标识**与 Settings 的选项表由单元测试互相校验
   （清单在 L1，文案在窗口，两者都不能替对方成为权威）。手写的路径不在选项表内，投影时按原值追加一项，
   保证配置文件里写的是什么就显示什么，且保存时逐字写回。

5. **许可与署名。** 随附图像取自 Unsplash，依 **Unsplash License** 分发（可免费下载、复制、修改、分发，
   不强制署名；禁止用其「复制同类或竞争性服务」）。署名（作者、原始链接、许可）记录于
   `data/wallpapers/CREDITS.md`；随附图像是一次**判断**，packager 可以整体删除 `data/wallpapers/`
   （此时按第 6 条降级）。不引入任何网络行为。

6. **降级与失败边界。**
   - 用户**从未选择**（`image` 缺席 → `DEFAULT_ID`）而默认文件缺失：记 `warn!` 并退到主题背景。这是**默认值**
     的失败，不是用户请求的失败，因此不进入错误态、不打扰用户。
   - 用户**显式**选择的内置 `id` 或路径不可用：与既有的坏路径同路径处理——退到主题背景并携带可读原因
     （`model::Unusable`），`tests` 覆盖。
   - `update` 仍不做 I/O：解析与解码经 `Task::perform` 在运行时线程池执行（ADR 0013）。
   - 解码上限（`decode::MAX_PIXELS` / `MAX_DIMENSION`）**不放宽**；随附图像在制作时已下采样到上限以内
     （`CREDITS.md` 记录方法），因此不需要新的上限。

## 失败、恢复与安全

- **初始化解码失败**：按第 6 条降级；已有帧不因新的失败请求而被清空（沿用既有 `apply` 语义）。
- **安装不完整**：把 `data/wallpapers/` 整个缺失视为「包未安装壁纸」——默认壁纸失败即主题背景，其余壁纸在选择
  时才报错。不会因缺文件而崩溃或黑屏。
- **缓存/陈旧**：无新增缓存；清单是编译期常量，路径在每次准备时解析，热重载（SIGHUP / `inoxctl reload`）
  与既有代次/命令结果机制一致。
- **输入边界**：`wallpaper.image` 是配置值，非用户输入的可执行内容；路径解析沿用既有的「相对配置目录」
  规则与逃逸检查由既有的组件路径校验覆盖（ADR 0009 决策 11 只约束 `[components]`，此处不新增特权）。
- **许可**：图像为本地文件，不触发网络，不上传数据（根级 §3.9）。

## 兼容、迁移与回退

- **行为变更**：`image` 缺席的默认结果改变（主题背景 → 默认壁纸）。文档、PRD 与组件说明同步更新；
  通告「想要主题背景请显式写 `none`」。键名与文件格式不变，`inox-config` 的解析器不需要迁移逻辑。
- **`inox-settings`**：`Field::WallpaperImage` 由 `Value::Text` 改为 `Value::Choice`；「默认」选项在写盘时
  **删除该键**（与空文本的旧行为一致），因此「保持默认」不会把默认值固化进配置。
- **消费方**：`inox-wallpaper`（解析语义）与 `inox-settings`（选择控件）同时落地；两者只共享 L1 清单，
  无新增跨组件依赖，`layering` 不变。
- **打包**：安装步骤需新增「复制 `data/wallpapers/` 到 `$XDG_DATA_DIRS/inox/wallpapers/`」；未做时按第 6 条降级，
  不阻断任何其他功能。不新增 Rust 依赖，`cargo deny` 图不变。
- **回退**：删除 `data/wallpapers/` 的安装并在配置写 `image = "none"`，或直接回退本 PR。

## 实施顺序与未决项

1. `inox-common::paths` 增加数据目录与壁纸目录解析（本 PR）。
2. `inox-config::wallpapers` 目录清单（本 PR）。
3. `inox-wallpaper` 采纳 `Selection`（默认/id/none/路径）与降级（本 PR）。
4. `inox-settings` 将 `WallpaperImage` 改为选择控件并补齐两种语言文案（本 PR）。

**未决项 / 复审触发条件：**

- **缩略图预览**：本 PR 起以**命名列表**呈现（复用既有选择控件），不画缩略图。真正的预览网格需要一条
  资源加载与缓存管线（`Task` 解码 → 句柄缓存），且不能在 `update` 内做 I/O；当出现第二个「需要图像预览」
  的界面时，抽出共享管线并补 ADR。
- **随附图像的许可**：Unsplash License 是否适合由发行版再分发，最终由 packager 判断；若上游要求更换，
  替换 `data/wallpapers/` 与清单即可，无需改动逻辑。
- **真机证据**：本 PR 不产生 E2/E3 的**主机**证据（二进制仍是普通窗口，ADR 0018 未解）；壁纸作为背景层生效
  的证据仍待 layer-shell 宿主可用。
