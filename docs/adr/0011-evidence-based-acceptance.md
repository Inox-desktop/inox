# ADR 0011: 以用户场景、证据等级与支持矩阵验收桌面

- 状态：proposed
- 日期：2026-10-16
- 决策者：架构组与产品负责人（待人类评审）
- 批准记录：待补；本草案不构成已实施门禁
- 关系：补充 ADR 0001、0003–0006 的交付约束；保留既有架构与历史验收，不追认新增标准已通过

## 背景

PRD 1.1 §6–§8、§13 将“CI 全绿”“创建输出”“管理两个窗口”“截图验证”作为主要里程碑判据。它们能发现编译和局部回归，但无法证明用户能完成任务、发生错误后能恢复，或在指定硬件上可用。ADR 0004 的骨架门槛与 ADR 0005 的纯色帧门槛有明确阶段价值，不应成为后续桌面质量的上限。

[Plasma 对照](../quality/plasma-reference.md) PL-01、PL-02、PL-06 显示，现行测试会检查唯一焦点、真实应用就绪与服务端状态；PL-09、PL-10 提供测试隔离、失败截图和审查证据的工程样例。PL-11 的重试配置同时说明，外部项目的做法仍需按 Inox 的风险独立取舍。

根级 AGENTS.md §3.1、§6、§9 要求 CI 验证、行为测试与人类审查。真实设备验收由人类使用 CI 发布物完成；headless 不能证明 KMS、libinput、挂起恢复或物理输入延迟。

## 决策驱动因素与备选

| 方案 | 收益 | 代价 / 不采用原因 |
|------|------|--------------------|
| 只提高覆盖率与 lint 门槛 | 成本低、容易自动化 | 高覆盖率仍可只有弱断言，无法证明用户任务与设备路径 |
| 每项 PR 都跑完整硬件矩阵 | 单次证据强 | 反馈时间与硬件成本过高，难以维护 |
| 分层证据 + 受影响场景 + 阶段完整验收 | 故障定位清晰、结论有边界 | 需要维护场景 ID、环境与证据存档；选择本方案 |
| 以 Plasma 功能全集作为 1.0 门槛 | 范围直观 | 与 PRD 非目标冲突，且该参考仓库并不涵盖完整桌面系统 |

## 决策

1. 采用[验收规范](../quality/acceptance.md)的 E0–E4、场景 ID、报告与里程碑映射。E0 静态、E1 逻辑、E2 组件、E3 Inox 集成、E4 人类硬件证据各有独立结论；高级证据不免除低级必需检查。
2. 每个行为 PR 标明适用场景与回归用例；接口变化在生产者、消费者及集成仓库验证；阶段交付跑全部累计适用项。历史里程碑保留当时结论，新标准通过情况另列差距表。
3. `inox-integration` 维护应用/硬件/协议/组件组合矩阵与执行入口。正式组合仍只消费发布 tag（ADR 0002）；候选组合锁 rev 预检不写成正式兼容声明。`compat.toml` 是组件版本表，不能独自替代测试报告或硬件支持清单。
4. 必需测试未发现、零用例、缺依赖、超时、跳过均不计通过；重跑保留首次失败。不能用自动重复直到成功掩盖偶发故障。基础设施故障要有诊断证据、责任 Issue 和修复后的新运行。
5. 运行环境隔离，驱动使用状态/事件等待，设置超时和清理检查。产物至少包括原始断言、环境、依赖与提交信息，失败时增加相关日志、截图/语义树。敏感内容仅使用人工样本并脱敏。
6. 覆盖率沿用核心 crate ≥70%，补充状态机拒绝/恢复分支及属性测试样本要求。覆盖率与像素差异均为补充，不能代替协议和语义断言；测试不能模拟掉被验收的核心路径。
7. 采用固定参考设备、明确统计口径与绝对预算。8 ms 合成 CPU 预算延续原 PRD 的 60 Hz 帧预算余量；100 ms 交互响应、稳定性时长、泄漏容限与重启限制是首版工程预算，并非 Plasma 实测结论。先登记设备与方法、建立基线，再按同一流程判断；后续调整须由数据支持并经人类审查，不能在失败后临时放宽。
8. 发布必须有无 P0/P1 的缺陷清单、真实硬件 Issue、回退证据、运行时组件许可证与 SBOM、人类批准。源代码许可证检查不覆盖系统组件的全部分发义务，也不能自动授权白名单外的核心依赖。

## 契约、失败与安全边界

“证据包”是交付格式约定，不新增线上服务或遥测。日志与测试截图属于本地/CI 测试产物，不能默认采集真实用户桌面。分支保护配置由既有规则管理，本 ADR 不授权代理绕过或直接修改保护。

CI 全绿证明对应提交在对应环境下通过所列检查；报告缺少 E4 时只能标记硬件待验收。`not-applicable` 必须有产品配置理由，不能用于免除锁屏安全、数据完整性或既有硬性规则。

## 迁移与验收

- 本 PR 只提交规范、模板和 ADR，不声称已在组件工作流实现全部门禁。
- 人类接受后，由各仓库 Issue 映射 B/R/W/O/X/D/C/S/Q/P/H/L 项到真实测试与 job；先补现有 M0–M2 的差距，再按 PRD §13 推进。不因既有功能“已完成”跳过复核。
- `inox-integration` 先完成 B02 的隔离/超时/收集/清理与 E3 入口；GUI 驱动、语义桥与协议宿主须先做 CI 原型，工具不足就是阻塞项。
- 本决策的实施验收：B01–B03、L01–L03；故意移除必需测试依赖、让用例超时与制造偶发失败时，报告必须失败且保留证据。
- 回退：若某自动化设施不可用，保留失败/未执行状态并修复设施；不得自动退回“日志可见即通过”。规范变更通过后续 ADR 和版本化文档完成。

## 后果

正面：交付结论能回答“哪个用户任务、哪个版本、哪个环境、凭什么通过”，避免用纯色帧或外部合成器测试证明 Inox 桌面完成；人类审查有具体证据。

负面：集成维护、人工验收与 artifact 存储成本增加；M4/M5/M6 的完成条件明显提高，可能推迟排期。硬件覆盖范围仍有限，因此支持声明必须严格受矩阵限制。

影响面：元仓库 PRD §6–§8、§13、README、质量文档；组件仓库工作流、测试与仓库级 AGENTS；`inox-integration` 的运行入口及报告。根级 AGENTS.md 的硬性规则不在本次修改。

复审条件：执行成本造成反馈不可用、产品支持矩阵改变、CI 能力扩展到硬件 runner，或连续两个发布发现验收通过但核心任务失效时，重新评估场景与采样；不能只删失败项。
