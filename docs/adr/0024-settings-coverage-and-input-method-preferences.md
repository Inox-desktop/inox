# ADR 0024: 设置覆盖现有配置，并持久化输入法启动偏好

- 状态：proposed
- 日期：2026-10-17
- 决策者：架构组（待人类评审）
- 批准记录：待补；当前会话要求完善设置并能修改输入法及壁纸，不视为架构接受。
- 关联：ADR 0009、0013、0014、0018、0023；验收 D04、Q01–Q03。

## 背景与备选

设置原有四页只能编辑十一项标量；键鼠、布局、壁纸、启动器和输出偏好已有消费者，
但只能手改文件。输入法只能用命令行选择，无法从设置保存下一次会话的选择。

保持手工编辑不能满足当前需求；在设置中直接启动输入法会绕过 ADR 0023 的专用连接授权，
直接修改设备又会绕过消费者的状态所有权；因此沿用配置写入方与消费者的边界。

## 本次增量

- 不增加 crate、IPC 或 Cargo 层级边，不更换核心依赖。四份配置仍使用现有 TOML 结构。
- 增加十个设置页，覆盖现有可编辑标量、输出列表、终端 argv 和分屏壁纸表。
  `inox-config` 继续持有 schema 与默认值，设置校验完整候选并逐键回读后才排队写入。
- `[input] input_method` 是新增的可选 argv 列表，默认空，保持既有配置不启动输入法。
  它是明确的用户选择，与 `--input-method` 使用同一监督器及专用授权连接；
  显式命令行参数优先，确定性 headless 后端继续不读取用户偏好。
  空程序名与 NUL 被 schema 拒绝，不解析 shell、不安装引擎、不改变锁屏权限。
- 保存仍只经过原子持久化入口。标量使用既有逐行补丁，集合使用 `toml_edit` 0.22
  的文档树替换集合并保留同级配置；`toml` 与 `toml_edit` 都是 MIT/Apache-2.0，
  已存在于锁文件中，本次将其声明为直接依赖，不升级版本。
- 旧代次保存回执不得消费新请求；部分文件失败后其他在途写入继续受控，
  实际成功的文件更新基线。所有在途写入结算之前禁止编辑、取消或另一次保存。

## 生效、迁移与回退

本次不实现消费方热重载；当前 `reload_config` 返回 Unsupported。
设置必须继续显示 saved-only，显示偏好只在下次会话启动读取。
没有服务端试用回退之前不提供实时显示模式切换或客户端倒计时。

旧配置缺少 `input_method` 时仍按默认空列表读取。旧程序会拒绝未知的新键：
降级前删除 `[input] input_method`，或恢复修改前的文件；已有命令行入口继续可用。
其他字段的 schema、默认值与权限策略不变。

自定义快捷键、显示试用/确认/超时回退，以及配置回执/状态回读的传输仍需后续具体提案及人类评审。
本次不以写盘成功代替这些能力，也不将本 ADR 的 proposed 状态视为实施新协议的许可。

## 验收与后果

CI 验证：全部可编辑数字边界与真实 schema 一致；草稿保存后重载值一致；
数组表、带引号表、内联/点号键集合能修改并保留同级文本；非法输入不排队写入；
陈旧回执、部分文件失败与继续在途写入均有回归；输入法参数逐字保留且命令行优先。
保留既有 1000 例属性测试、双语目录和真实控件树像素/点击断言。

责任 crate：`inox-settings`、`inox-config`、`inox-compositor`。证据范围为 E0/E1，
waydriver、真实多屏及真实引擎的 E2/E3 仍由宿主 CI/硬件验收负责，不据此宣告 D04 全部完成。

收益是用户可从设置维护桌面偏好；成本是结构化集合、输入焦点与在途失败路径的维护。
待消费方支持真实应用回执时复审 saved-only；引擎发现、安装和词库管理需要独立需求。
