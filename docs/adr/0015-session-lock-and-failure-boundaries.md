# ADR 0015: 会话监督、锁屏与特权能力按失败边界设计

- 状态：proposed
- 日期：2026-10-16
- 决策者：架构组与安全审查者（待人类评审）
- 批准记录：待补
- 关系：补充 ADR 0003、0006、0007；纠正 PRD 原“合成器崩溃后恢复窗口”的无条件承诺；不批准新的认证依赖或协议 XML

## 背景

原 PRD §8 承诺合成器崩溃后“重新拉起并恢复窗口”，却未定义客户端重连/状态保存机制；重启合成器不能自动恢复已断开的 Wayland 连接或应用未保存内容。PRD §10 要求 session-lock，§13 M5 却只以“锁屏可解锁”验收，也未覆盖锁定中 UI 退出、新输出、捕获和挂起竞态。

PL-12 的认证 UI 展示了提示/错误/成功/挂起前清理的生命周期，不能证明 KWin/kscreenlocker 的安全边界。历史 `design/security` 提案也不能替代当前威胁模型，见 [Plasma 对照](../quality/plasma-reference.md)。本 ADR 自行定义 Inox 的边界与验证义务，具体协议行为以 `inox-protocols` 锁定 XML 和实现审查为准。

核验依据：已读取 `wayland-protocols` 0.32.13 所附 [ext-session-lock-v1.xml](https://docs.rs/crate/wayland-protocols/0.32.13/source/protocols/staging/ext-session-lock/ext-session-lock-v1.xml)，其 locked 事件要求所有输出已呈现安全锁定帧，客户端死亡不能使会话解锁；安全恢复由合成器策略决定。本次读取用于校对约束，消费者实际版本仍以锁文件和 XML 记录为准，不自动升级依赖。

## 威胁与失败范围

保护对象：锁定期间的桌面画面、输入、剪贴板/捕获能力、用户配置与会话资源。考虑不可信 Wayland 客户端、沙箱应用、异常/无响应服务、锁屏 UI 崩溃、输出变化与恢复路径。

本模型不声称抵御已控制内核、认证系统或用户全部进程的攻击者；同 UID、客户端自报 app_id/PID 或可连接普通 Wayland socket 不等于应授予截屏/注入/输出管理等能力。授权检查必须在拥有资源的服务端执行。

## 备选方案

| 方案 | 收益 | 代价 / 不采用原因 |
|------|------|--------------------|
| 顶层全屏窗口或 layer-shell 遮罩作为锁屏 | UI 容易实现 | 不能证明输入/其他层隔离或 UI 崩溃后安全；拒绝 |
| 所有服务交给统一无限重启策略 | 容易恢复部分进程 | 重启风暴、锁屏丢失、错误隐藏；拒绝 |
| 合成器维护锁状态，认证与 UI 分离，session 按故障域监督 | 安全状态不依赖单个 UI，故障可诊断 | 需要认证边界与故障注入；选择本方案 |
| 宣称合成器重启即可恢复应用 | 用户预期好 | 缺少协议/客户端支持，无法验证；移除该承诺 |

## 决策

### 会话启动与监督

1. `inox-session` 管理运行时依赖和子进程归属，不链接 L3 UI 或合成器内部状态。合成器创建并可响应 socket 后才启动依赖组件；完整 ready 包含核心 Shell 入口与一次实际请求往返，不以 `spawn` 成功判定。
2. 必需/可选组件分级登记。必需项启动超时/拒绝导致明确启动失败或可诊断退化；可选项失败不能拖垮应用。每组件 60 s 内最多自动重启 3 次，使用有界退避并清理旧子进程，超限停重试并反馈；该预算是首版防风暴策略，不是通用性能承诺。
3. Shell/面板/通知崩溃时仅恢复对应失败域，合成器与应用保持；重新连接后按 ADR 0013 重建状态。注销按逆序停止并在 10 s 内清理子进程、socket 和设备归属，升级终止信号的条件可观察。
4. 合成器崩溃属于会话级故障：记录原因、终止/重建会话并呈现失败，不能声称恢复原窗口或未保存数据。若将来支持客户端恢复，需单独 ADR 定义协议、客户端参与范围、状态安全与恢复证据。
5. lid close 不是默认注销或退出合成器的理由；空闲/电源策略结合外接输出与用户配置决定是否请求挂起。设备后端不能自行把电源策略变成退出事件。

### 锁定与认证

- 锁定状态由合成器所有，`inox-lock` 是经 session 启动的可信锁屏客户端。采用 `ext-session-lock-v1`，不把 layer-shell 最高层等同于安全锁；精确锁完成/解锁时序必须对照锁定版本 XML 实现和测试。
- 至少区分 unlocked、locking、locked、unlocking 与 locked-without-ui；声明 locked 前确保所有现存输出已安全遮蔽并隔离普通输入。锁定期间新增输出先遮蔽后显示；普通 popup/grab、任务切换、通知正文不能绕过。
- 锁屏客户端退出、认证服务失败或超时都保持锁定，必要时呈现安全空白并由 session 有界重启可信 UI；不能在 destroy/disconnect 时自动解锁。恢复/接管必须符合协议允许的生命周期；若需扩展由单独协议评审批准，不能假定支持第二个客户端直接接管。
- 解锁只接受可信认证结果。密码校验使用经过审查的系统认证边界，不自研密码哈希/校验，也不把用户密码交给合成器或普通 Shell。PAM/其他认证机制、helper 权限/沙箱、凭据传递与清理是 M5 实现前的必要评审项，未确定即为阻塞，不能以测试桩算认证完成。
- 凭据不写日志、通知、剪贴板或截图；失败认证有限流与可读反馈。UI 隐藏、取消、切换用户/认证器或挂起时清理敏感输入，不依赖动画结束来执行安全清理。

### 空闲与挂起

- `inox-idle` 管理空闲计时/抑制，使用协议状态，不轮询进程猜测活动；抑制不阻止手动锁定。触发顺序为准备锁定→收到锁完成确认→允许挂起；锁定失败按明确策略阻止/取消挂起，不能先休眠再寄望恢复时补锁。
- 集成系统会话的挂起准备/抑制机制，确认时序有上限与失败结果。恢复后仍 locked，VT 与设备恢复不能重置锁状态；未认证时不得出现普通桌面帧。

### 特权接口

| 能力 | 权威校验点 | 缺授权或锁定时 |
|------|------------|----------------|
| 输出管理、私有配置控制 | 合成器/配置拥有者 | 拒绝请求并返回结果，不接收客户端自报身份即放行 |
| 截图、屏幕共享、远程输入/虚拟设备 | 捕获/输入拥有者与获批准的 Portal/权限代理 | 默认不可用；撤销存量能力，锁定中止已有会话并防旧帧泄漏 |
| session lock 与解锁 | 合成器 + 可信锁屏/认证边界 | 普通客户端不能夺取可信锁屏角色或伪造成功 |
| 剪贴板/拖放 | seat/selection 拥有者 | 遵守焦点、serial 与授权生命周期；限制未授权读取和锁定旁路 |

授权绑定到 session 建立的可信连接/能力句柄与其生命周期，普通 app_id、进程名或 UID 检查不足以表达能力。具体传递机制须在 XML/IPC 设计中评审；不在本 ADR 臆造当前 v1 已具备令牌。撤销、进程退出、版本不支持、乱序/超限请求均是契约测试的一部分。

协议清单要区分仅生成绑定、服务端广告、完成行为与通过验收；广告某全局不代表所有权限路径合格。未实现的捕获/输入法能力不能因绑定已导出而标为支持。`inox-portal` 的建仓/依赖/协议范围仍需独立 ADR，本提案不提前创建。

## 验收、迁移与回退

实施前建立 S01–S05 的状态机与系统边界测试。E3 保留一个持续记录输入/帧/selection 的普通客户端，逐一注入锁 UI 崩溃、认证失败、热插拔、旧抓取请求与服务重启，断言锁定期间零泄漏；E4 用 CI 发布物完成真实挂起/VT 与多屏恢复。

锁屏/权限路径引入前必须完成人类安全审查，实际认证依赖、许可证与最小 helper 权限在实现 ADR/PR 记录，不能用一个 proposed 概念文件替代批准。回退遇到不支持的锁定/认证组合时拒绝启动该安全功能并阻塞“日常可用/发布”声明；已锁定会话发生故障始终保持封锁。

## 后果

正面：锁状态与 UI 进程失败解耦；监督不会把故障变成无限重启；去除无法兑现的窗口恢复承诺，权限校验有明确服务端位置。

负面：M5 增加真实认证、挂起准备、故障注入与人工安全评审成本；安全空白可能暂时牺牲交互，需要恢复入口；合成器崩溃仍会损失客户端连接，必须如实披露。

影响面：`inox-session`、`inox-idle`、`inox-lock`、`inox-compositor`、`inox-protocols`、`inox-notifications`、`inox-xwayland`、集成仓库与 PRD §2.3/§8/§10/§13。根级权限、unsafe、网络与许可证规则不放宽。

复审条件：新增远程桌面、多用户切换、多 seat、Portal 后端、客户端会话恢复或认证机制变更时重新评估威胁边界，并扩展对应场景。
