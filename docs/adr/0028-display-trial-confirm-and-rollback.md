# ADR 0028: 显示设置的试用、确认与超时回退

- 状态：proposed
- 日期：2026-10-17
- 决策者：架构组（待人类审查）
- 关联：ADR 0009、0012、0014、0019、0020、0026；PRD §9、§13；验收 C02、C03、D04、O03、E4。

## 背景

ADR 0026 把运行中配置重载拆成两半：主题、语言、面板、启动器、壁纸、通知与输入设备
可以热应用，而**输出模式、位置与缩放被明确拒绝**（`outputs: live display changes
require server-side trial and rollback`），只保留文件供下次会话读取。理由是显示模式
切换可以让屏幕变成用户无法操作的黑屏：写盘成功、消费方回执成功，都不等于用户
还能看见并确认这次改动。ADR 0014 第 5 条已经把结论写成义务：**「设置关闭后设备确认
超时与回退仍由服务端执行」**。

本次用户直接要求在设置里做到两件事：显示部分的修改可以热重载；改动后弹出确认框，
30 秒内没有点「确认修改」就恢复原来的设置，且**只对显示页**如此。这两件事必须一起
实现才有意义——只做前者就是 ADR 0026 拒绝的那种「以回执冒充可用」，只做后者则没有
可回退的对象。

## 备选方案

| 方案 | 收益 | 代价 / 结论 |
|------|------|-------------|
| 维持 ADR 0026 的拒绝：显示改动只在下次会话生效 | 零风险，无需新接口 | 不满足用户当次要求；用户改分辨率必须重启会话，这正是要解决的问题。不采用 |
| 设置窗口自己计时并回退（只扩展现有 `Reload`） | 不新增接口 | 设置进程崩溃、被杀或断连时，试用中的模式永远留在屏幕上；违反 ADR 0014 第 5 条。不采用 |
| 合成器侧试用：新增**附加**的 `org.inox.Configuration2`，由合成器持有 30 秒期限，设置窗口倒计时并主动回退 | 期限与回退由设备持有者执行；设置消失也能恢复；v1 调用方不受影响 | 多一个接口与一份逐组件回读代码；`Confirm`/`Rollback` 需要代次比较。选择本方案 |
| 通过 logind/会话重启切换模式 | 复用现成机制 | 会话整体重建，窗口、客户端和未保存状态全部丢失；不是「热重载」。不采用 |

## 决策

### 协议

- 新增 `crates/inox-protocols/protocol/configuration-v2.md`，接口 `org.inox.Configuration2`，
  与 v1 **在同一对象路径** `/org/inox/Configuration` 上同时提供。v1 的 `Reload` 语义不变，
  因此这是**附加**能力，不是破坏性变更：未升级的调用方继续用 v1，新调用方按需选 v2。
- `Trial(t generation, s expected) -> (t generation, s applied)`：与 `Reload` 相同的
  候选读取、`snapshot()` 逐字比对与逐字段校验，但**输出偏好是临时的**。合成器在应用前
  记下当时的输出偏好，应用成功后才回复；回复成功后 30 秒内没有 `Confirm`，合成器自己回退。
- `Confirm(t generation) -> (t generation, s applied)`：把该代次的试用转为正式状态并撤销期限。
  代次不等于当前试用时**拒绝**——迟到的确认不能把用户没看见的模式固定下来。
- `Rollback(t generation) -> (t generation, s applied)`：立刻恢复试用前的配置。**幂等**：
  代次未知（已回退、已超时或被更晚的请求取代）时不报错，返回当前快照。设置窗口在
  30 秒到期时调用它，合成器的期限是同一件事的兜底，两者重复执行的结果相同。
- 同一消费方同一时刻只允许一个试用；第二个 `Trial` 返回失败。`Reload`（v1）携带与当前
  生效状态不同的 `outputs` 时仍然拒绝，并指向 `Trial`——SIGHUP 与 `inoxctl` 没有确认
  通道，不能让它们触发无人确认的模式切换。
- 传输、权限与错误边界沿用 v1：只重读消费方启动时发现的配置目录，不接受路径、命令或
  资源正文；仅同一用户的会话总线可达；请求截止 5 秒、设置侧超时 6 秒。新增的
  `Confirm`/`Rollback` 不携带快照，只携带代次。

### 状态所有权与生命周期

- **期限归合成器**：`GpuBackend::rescan` 已经能按新的 `OutputConfig` 重新选择模式、缩放与
  位置，试用只是把「当前偏好」变成一个可回滚的临时值。合成器持有 `previous`（试用前的
  输出偏好）与到期定时器；到期或失败时用 `previous` 再 `rescan` 一次并刷新拓扑。
- **只有输出偏好是临时的**：主题、语言、输入设备与平铺参数不属于「显示」，试用回退
  不把它们退回去，文件也只恢复 `outputs` 一个键。这与 ADR 0014「不承诺跨组件全局原子性」
  一致：一次 Apply 里同时改了别的页，用户对别的页的修改不受显示试用超时影响。
- **回退只走既有写入路径**：设置窗口把 `outputs` 的草稿值放回改动前的值，再走一次
  `draft.edits()` → `document.patch` → `persist::save`（ADR 0014 的原子写入与外部编辑检测、
  只重写被改的键），然后重新请求消费方应用。不新增第二份写文件实现。
- **界面不得声称未确认的成功**：试用期间状态行与弹窗说明「已应用、待确认」；只有
  `Confirm` 的回读（或回退后重新应用的回读）才显示「已生效」。倒计时用尽而未确认时，
  窗口显示「已恢复原来的设置」以及未能联系到合成器时的失败原因。

### 边界与限制

- **物理后端**：试用作用于真实 connector（模式/缩放/位置）。**headless 后端**的输出由
  命令行 `--output` 决定，`compositor.toml` 的 `outputs` 在该路径上本来就不生效，因此
  headless 继续拒绝 `outputs` 的热应用；设置窗口看到的是「已保存、未生效」，弹窗不出现。
  这是刻意保留的确定性边界（ADR 0012、ADR 0019）。
- **合成器进程消失**：试用期间合成器崩溃或被替换时，`Rollback` 会失败；设置窗口**仍然**
  把 `outputs` 恢复成改动前的值并如实报告「合成器未能恢复」，使下一次会话不会读到
  用户没有确认的模式。
- **模式本身不可用**：`rescan` 对不支持的请求保持该输出原状（ADR 0019 的逐输出拒绝）。
  试用只有在全部请求的输出都可应用时才回复成功；任何失败都先恢复 `previous`，再返回失败。
- 安全边界不变：不新增系统总线、网络监听或额外权限；试用不能跨越用户边界。

### 版本与迁移

- 不改变 `config.toml` / `compositor.toml` 的 schema、默认值或字段名，因此不涉及配置迁移。
- 接口按 ADR 0006/0026 的版本策略以新版本名出现；v1 保留并被继续服务，删除 v1 需要
  另一次 ADR。若将来第二个消费方（如会话服务）需要试用，应把 v2 泛化为「带确认的应用」，
  而不是为每个消费方各造一个接口。

## 验收与实施顺序

1. 合成器：试用状态机是纯逻辑（代次、期限、确认/回退判定），必须有单元测试；物理路径的
   应用复用 `GpuBackend::rescan` 与 `InoxState::apply_outputs`，不新增拓扑入口。
2. 设置：`app::State` 增加试用子状态，超时、确认、迟到回执、只对显示页生效、回退写入
   只改 `outputs` 键——全部以单元测试驱动，不依赖屏幕；`tests/render.rs` 增加一个
   弹窗场景（有倒计时、两个按钮、键盘可达）。
3. 文案全部走 Fluent（en-US 与 zh-CN 同步，`tests/catalog.rs` 断言齐备）。
4. **证据边界**：headless CI 只能证明接口契约、状态机与像素绘制；「真实显示器切换后
   30 秒未确认确实回到原来的模式」属于 E4 真机验收，不由本 ADR 的 CI 结果推断。

## 后果

- 收益：显示设置第一次可以像其它页一样热应用；危险的模式切换有确认与自动回退，
  用户不会因为一次误点永久失去画面；设置窗口消失时由设备持有者兜底。
- 成本：多一个 D-Bus 接口、合成器多一个到期定时器与一份 `previous` 状态、设置窗口多一个
  模态状态与倒计时订阅。回退是第二次写盘，因此一次被放弃的显示改动会产生两次
  `persist::save`（各自原子、各自检测外部编辑）。
- 复审触发条件：layer-shell 宿主、实时输出拓扑（热插拔期间试用）或输入法原子替换落地时，
  重新评估本 ADR 的接口形状；跨用户/远程配置需要独立的授权与提交协议。
